# Спецификация Frontend — «Календарь смен»

Структура «собственник → бизнес → точки», начало цикла сотрудника и обработка пересечений требуют согласования с куратором. Ручное подключение аккаунта также остаётся предложением. Приглашения, управление ролями, редактирование / удаление смен, фактические выходы, отчёты, чат и уведомления относятся к следующим спринтам.

## 1. Страницы → URL → назначение

Рабочие страницы используют префикс `/app/b/:businessId`. В таблице их пути указаны относительно него; `/login`, `/onboarding` и `/profile` — самостоятельные URL.

| Страница | URL | Назначение |
|---|---|---|
| Вход | `/login` | Войти через Яндекс ID, повторить неудачный вход |
| Первое подключение | `/onboarding` | Создать бизнес или получить инструкцию подключения к команде |
| Точки | `/workplaces`, `/workplaces/:id` | Список и карточка доступной точки |
| Сотрудники | `/employees`, `/employees/:id` | Справочник и карточка сотрудника |
| Календарь | `/calendar` | Расписание по точке или сотруднику, просмотр деталей смены |
| Генерация | `/schedule/generate` | Обязательная генерация: предварительный график по циклу и его сохранение |
| Профиль | `/profile` | Данные аккаунта, его ID, доступные бизнесы и роли, выход |

Детали смены открываются в панели календаря; ID выбранной смены сохраняется в параметре `shift_id` URL. Отдельная страница и отдельный API карточки смены не требуются.

## 2. Содержимое страниц

| Страница | Данные и представление | Кнопки |
|---|---|---|
| Вход | Название сервиса, состояние авторизации, понятная ошибка входа | «Войти через Яндекс ID», «Повторить» |
| Первое подключение | Выбор создания бизнеса или подключения; собственный ID аккаунта и инструкция | «Создать бизнес», «Скопировать ID», «Обновить доступ», «Выйти» |
| Точки | На компьютере таблица, на телефоне карточки: название, адрес, пояс; в карточке также телефон и описание, если заполнены | Поиск, «Добавить», «Расписание», «Редактировать» |
| Сотрудники | Имя, доступные связанные точки, статус «Подключён» / «Не подключён»; контакты по правам | Поиск, фильтр точки, «Добавить», «Редактировать», «Расписание» |
| Календарь | Неделя / месяц; сетка на компьютере, список на телефоне; смены с сотрудником, точкой и временем | Фильтры, «Сегодня», предыдущий / следующий период, «Обновить», «Создать смену», «Сформировать график» |
| Генерация | Параметры цикла, локальный список кандидатов, количество смен, суммарная длительность, возможные пересечения | «Предварительный просмотр», «Создать смены», «Назад» |
| Профиль | Имя, доступные email / телефон, внутренний ID аккаунта, бизнесы и роли | «Скопировать ID», «Обновить доступ», «Переключить бизнес», «Выйти» |

В деталях смены: сотрудник, точка, даты и время начала / окончания, часовой пояс, плановая длительность, комментарий. Доступен просмотр; кнопки переноса, удаления и отметки выхода появятся в следующих спринтах.

**Права интерфейса:**

- Собственник видит все рабочие разделы и формы своего бизнеса.
- Администратор читает доступные точки и сотрудников, создаёт смены в разрешённых точках. Формы изменения точек и сотрудников ему недоступны.
- Сотрудник видит «Мои смены», «Мои точки» и «Профиль». Его `employee_id` берётся из сессии; общего справочника и выбора чужих сотрудников нет.
- Меню и действия строятся по правам из backend; прямой переход по URL также проверяет доступ.
- Администратор и собственник могут создавать смены вручную и через генерацию в пределах своих прав. Доступные точки и права берутся из сессии и ответов API.

## 3. Действия → формы → состояния

### Формы и результат

| Действие | Поля формы | Результат |
|---|---|---|
| Создать бизнес | Обязательные название и часовой пояс | После ответа сервера обновляется сессия, открываются точки нового бизнеса |
| Создать точку | Обязательные название и часовой пояс; адрес, телефон, описание — необязательные | Точка появляется в списке |
| Изменить точку | Название, адрес, телефон, описание; пояс только для чтения | Список и карточка обновляются |
| Создать / изменить сотрудника | Обязательные имя и одна или несколько точек; email, телефон, ID аккаунта — необязательные | Обновляются справочник, карточка и статус подключения |
| Подключить аккаунт | Собственник вводит переданный сотрудником `user_id` в форме сотрудника | Backend связывает аккаунт; сотрудник нажимает «Обновить доступ» и получает расписание |
| Создать смену | Обязательные точка, сотрудник, даты и время начала / окончания; комментарий — необязательный | После подтверждения сервером обновляется календарь |
| Сформировать график  | Точка, сотрудник, X рабочих / Y выходных, начало / конец периода, время начала, длительность; поле начала цикла — рабочая гипотеза до согласования | Локальный просмотр → подтверждение → сохранение пакета → обновление календаря |
| Изменить фильтры / период | Точка, сотрудник, дата, неделя / месяц | Обновляются URL и расписание |
| Выйти | Без полей | После завершения сессии очищаются данные аккаунта и открывается вход |

Формы открываются в диалоге / панели, на узком экране — на весь экран. Есть «Сохранить» и «Отмена»; уход с изменённой формы требует подтверждения. При сохранении повторное нажатие блокируется, при ошибке ввод сохраняется.

**Подключение:** сотрудник сначала входит и передаёт собственнику внутренний User.id, показанный в профиле или инструкции подключения. Контактный email не подключает аккаунт автоматически. После подключения поле ID недоступно для перепривязки; роль пользователь самостоятельно не назначает.

### Проверки и время

- Названия и имя не пустые; выбрана хотя бы одна точка сотрудника.
- В форме смены выбираются сотрудник и точка из доступных данных; сотрудник должен быть назначен на точку. При смене точки неподходящий выбранный сотрудник сбрасывается.
- Конец позже начала; длительность — 1–1440 минут. Для ночной смены пользователь явно указывает следующую дату.
- В форме и деталях показывается время точки. Календарь выбранной точки использует её пояс; при просмотре нескольких точек по сотруднику предлагается пояс бизнеса с явной подписью.
- Границы периода переводятся в моменты времени для API. Несуществующее локальное время отклоняется; для неоднозначного требуется выбор смещения.
- Генерация: X / Y — целые 1–31; период до 31 календарного дня включительно. Одна точка, один сотрудник, один кандидат на рабочий день. Начало цикла согласуется с куратором: для чернового расчёта предлагается явно заданный первый рабочий день, не позже начала периода; это рабочая гипотеза, а не утверждённое правило.
- Изменение параметров генерации сбрасывает просмотр. Пустой список не отправляется; смена последнего дня не обрезается.
- Frontend может показать возможные пересечения, но не вводит собственный запрет, пока правило не согласовано. Решение об ошибке принимает backend: при конфликте пакет целиком отклоняется; существующие смены не заменяются. Трактовка 5/2 как будней также требует согласования.

### Состояния интерфейса

| Состояние | Поведение |
|---|---|
| Загрузка | Индикатор; зависимые действия недоступны |
| Пустые данные | Объяснение и доступное действие: создать точку, сотрудника или смену |
| Нет совпадений | Предложение изменить фильтры |
| Частичная загрузка | Явное обозначение неполного списка; загрузка следующих страниц |
| Сохранение | Заблокирована повторная отправка, виден прогресс |
| Успех | Подтверждение и обновление затронутых данных после ответа сервера |
| `422` | Ошибки около соответствующих полей, ввод сохранён |
| `409` | Сообщение о конфликте смен или связи аккаунта; ввод сохраняется для исправления, автоматического повтора нет |
| `401` | Защищённые данные скрываются, предлагается повторный вход |
| `403` / `404` | Сообщение о недоступности и переход к разрешённому разделу |
| Нет сети / ошибка сервера | Понятное сообщение; чтение можно повторить, запись без сети недоступна. При неопределённом результате записи — состояние ниже; загруженные ранее данные отмечены как неактуальные |
| Ответ записи потерян | Результат неизвестен; повторная запись автоматически не отправляется. Кнопка «Обновить данные» выполняет GET, затем пользователь проверяет список / карточку / календарь |

При неизвестном результате форма сохраняет ввод и пометку о необходимости проверки. Отсутствие записи в одной выборке не доказывает, что запрос не выполнился. Повторное сохранение возможно только по явному решению пользователя после проверки; интерфейс не обещает защиту от дублей. `request_id` можно скопировать из сообщения об ошибке.

## 4. Навигация

- При запуске загружается сессия. Без неё — вход; без бизнеса — первое подключение; при нескольких бизнесах — выбор; затем календарь выбранного бизнеса.
- Меню собственника / администратора: «Календарь», «Точки», «Сотрудники», «Профиль» с учётом прав. Меню сотрудника: «Мои смены», «Мои точки», «Профиль».
- Из списка открывается карточка; из карточки точки / сотрудника — календарь с нужным фильтром.
- Из календаря открываются детали смены, создание или генерация. После сохранения восстанавливаются период и фильтры.
- Период, режим и фильтры календаря хранятся в URL. Прямые ссылки, обновление страницы и «Назад» работают после проверки сессии и доступа.
- При переключении бизнеса сбрасываются формы, выборки и фильтры предыдущего бизнеса. Поздний ответ старого запроса не заменяет данные текущей страницы.

**Браузер / PWA:** интерфейс адаптивный, основные действия работают в браузере. Целевые среды из ТЗ — Chrome на Android 11+ и Safari на iOS 12+; совместимость проверяется отдельно. В первом спринте — рабочая развёрнутая версия и основа PWA, полноценное завершение PWA — следующие спринты. Установка не обязательна для работы; при отсутствии возможности установки остаётся браузерный сценарий. Offline-запись и push не входят в этот спринт.

## 5. Связь с Backend

Ниже приведены все **14 эндпоинтов** из backend_specification(1).md. Для относительных путей `/workplaces`, `/employees`, `/shifts` применяется префикс `/api/businesses/:business_id`.

| API | Действие / что передаётся | Что отображается или обновляется |
|---|---|---|
| `GET /api/auth/yandex/start` | Кнопка входа; `return_to?` | Браузер переходит к Яндекс ID |
| `GET /api/auth/yandex/callback` | Провайдер возвращает `code`, `state` либо ошибку на backend | Backend завершает вход и перенаправляет во frontend; frontend обновляет сессию |
| `GET /api/session` | Запуск, возврат после входа, «Обновить доступ»; cookie | Аккаунт и его ID, бизнесы, роли, права, собственный `employee_id`, доступные точки |
| `POST /api/auth/logout` | «Выйти»; текущая сессия | При `204` очищаются данные и открывается вход |
| `POST /api/businesses` | `name`, `timezone` | Новый бизнес и доступ собственника |
| `GET /workplaces` | `q?`, `cursor?`, `limit?`; для карточки — `id` | Доступные точки / карточка и варианты выбора в формах |
| `POST /workplaces` | `name`, `timezone`; `address?`, `phone?`, `description?` | Созданная точка в списке |
| `PATCH /workplaces/:id` | Изменённые `name`, `address`, `phone`, `description` | Обновлённая точка |
| `GET /employees` | `q?`, `workplace_id?`, `cursor?`, `limit?`; для карточки — `id` | Справочник / карточка, точки и статус подключения; варианты выбора сотрудника |
| `POST /employees` | `full_name`, `workplace_ids`; `email?`, `phone?`, `user_id?` | Созданный сотрудник и статус подключения |
| `PATCH /employees/:id` | Изменённые `full_name`, `email`, `phone`, `workplace_ids`, `user_id` | Обновлённый сотрудник; карточка и статус подключения актуализируются по ответу / повторному GET |
| `GET /shifts` | `from`, `to`; `workplace_id?`, `employee_id?`, `cursor?`, `limit?`; для деталей — только `id` | Расписание либо одна смена с подписями и длительностью |
| `POST /shifts` | `workplace_id`, `employee_id`, `starts_at`, `ends_at`; `comment?` | Подтверждённая смена, затем обновлённый календарь |
| `POST /shifts/bulk` | `shifts`: 1–31 объект с полями обычной смены после локального просмотра | `created_count`, `shift_ids`; при конфликте — ошибка без частичного сохранения |

**Правила интеграции:**

- Карточки точек, сотрудников и смен используют фильтр `id` соответствующего списка. Он возвращает один объект или `404`; для одной смены период не передаётся.
- Списки читаются с пагинацией. Календарь загружает все страницы периода; неполный ответ не показывается как полное расписание. Для генерации запрашиваются имеющиеся смены, пересекающие весь диапазон кандидатов, включая ночное окончание.
- Интервал календаря — `[from, to)`. `starts_at` / `ends_at` передаются в ISO 8601 с `Z` или явным смещением; часовой пояс устройства не подменяет выбранный пояс.
- При создании и изменении отправляются только перечисленные поля. После PATCH данные обновляются по ответу сервера; обнаружение одновременных изменений контрактом не предусмотрено.
- POST и PATCH не повторяются автоматически после таймаута, сетевого сбоя, неопределённой ошибки сервера или повторного входа. Для проверки результата используются существующие GET.
- В Shift нет отдельного поля часового пояса: для отображения используется `timezone` соответствующей Workplace из списка или карточки точки. Если пояс недоступен, время показывается в UTC с явной подписью, без подстановки пояса устройства.
- Cookie сессии обрабатывается браузером; токены Яндекс frontend не получает. Изменяющие запросы соблюдают согласованную с backend защиту от CSRF.
- Точные JSON-ключи оболочки списков, структуры прав и ошибок полей уточняются при согласовании API. Поля форм и названия параметров выше соответствуют backend.

**Первый спринт завершён по frontend**, когда собственник может создать бизнес, создать / изменить точку и сотрудника, подключить аккаунт, назначить смену вручную и сформировать график, а сотрудник — войти и увидеть расписание. Генерация проверяется по согласованным правилам начала цикла и пересечений; основной сценарий — на компьютере и телефоне в развёрнутой версии.
